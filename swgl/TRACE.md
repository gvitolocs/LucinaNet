# swgl call traces (`LUCINANET_GLTRACE`)

A recording of every call that crosses swgl's `extern "C"` boundary (the `cxx` module in `src/swgl_fns.rs`),
so that a WebRender session can be replayed offline, with no Servo, by `raster/gltrace`. Its purpose is to
compare swgl's C++ rasterizer with a Rust one pixel by pixel, and to time them.

## Turning it on

- Set `LUCINANET_GLTRACE=<dir>` before the first `swgl::Context::create()`. The `CreateContext` dispatch function
  reads it once (`trace::init`). The trace goes to `<dir>/trace-<pid>.bin`, and swgl prints that path on stderr.
- Every one of the 100 `cxx` functions has a dispatch function of the same name and signature in `swgl_fns.rs`, and
  nothing else calls `cxx`. With tracing off, a call costs one relaxed atomic load more than before.
- `Context::trace_frame()` writes a `FrameMarker`. LucinaNet calls it at the start of `SoftContext::present` and
  of `SoftContext::with_frame` (`crates/lucinanet-servo/src/soft.rs`).
- `swgl::trace::finish()` (hidden) flushes and closes the trace. Tests call it before they replay in the same
  process.

## File layout

```
magic    8 bytes  "SWGLTRC1"
records  u16 op | u32 thread | u32 payload length | payload
```

Everything is little-endian. `thread` is a small number given to each thread when it first records anything
(0 is the first thread). A record is written after its call returns, and one mutex orders the records. The file
is flushed at every `FrameMarker` and `DestroyContext`. If the process dies in the middle of a record, readers
stop at the last whole record (`TraceReader::truncated`).

Tracing stops for good, with a message on stderr, when a call cannot be recorded exactly: a texture upload,
read-back or clear in a format gl.cc does not accept, or a `MapBuffer` on a buffer whose size no `BufferData`
gave. The file is still valid up to that point.

## Encoding

| In the signature | In the payload |
|---|---|
| `GLenum`, `GLuint`, `GLbitfield` | `u32` |
| `GLint`, `GLsizei`, `i32` | `i32` |
| `GLboolean` | `u8` |
| `GLfloat` / `GLdouble` | `f32` / `f64` |
| `GLintptr`, `GLsizeiptr` | `i64` |
| `*mut c_void` context, `*mut LockedTexture` | `u64` handle value. The replayer maps it to its own |
| `*const GLvoid` vertex attribute offset | `u64`, passed through unchanged |
| `YuvRangedColorSpace` | `u8` discriminant |

Composite values used below:

- **bytes**: a `u32` length, then the bytes.
- **string**: a `u8` flag. 0 means a null pointer. 1 is followed by **bytes** (no NUL).
- **data**: a pointer to memory the call reads or writes. A `u8` flag:
  - `0` `DATA_NULL`: a null pointer.
  - `1` `DATA_INLINE`: followed by **bytes**, the memory itself.
  - `2` `DATA_OFFSET`: followed by a `u64`. A buffer was bound for the call (unpack or pack buffer), so the
    pointer was an offset into it.
- **dims**: three times a `u8` flag and, if it is 1, the `i32` swgl wrote through that out-pointer (width,
  height, stride). The flag is 0 where the caller passed null.

**pixels** (`put_pixels`) is one of:

- `DATA_OFFSET, u64`: a buffer is bound to `PIXEL_UNPACK_BUFFER`, so `data` is an offset into it.
- `DATA_NULL`.
- `DATA_INLINE, i32 row_length, u32 bpp,` **bytes**: the `height` rows of `width × bpp` bytes, packed.
  `row_length` is the `GL_UNPACK_ROW_LENGTH` the call saw (0 means `width`). The replayer spreads the rows back
  out to that pitch.

`bpp` comes from `trace::bytes_per_pixel`, which accepts exactly the `(format, type)` pairs that gl.cc's
`internal_format_for_data` accepts: RED/UNSIGNED_BYTE 1, RGBA or BGRA/UNSIGNED_BYTE or UNSIGNED_INT_8_8_8_8_REV 4,
RGBA/FLOAT 16, RGBA_INTEGER/INT 16, RG/UNSIGNED_BYTE 2, RGB_422_APPLE/UNSIGNED_SHORT_8_8_REV_APPLE 2,
RED/UNSIGNED_SHORT 2, RG/UNSIGNED_SHORT 4. The clear value size (`trace::clear_value_size`) is the number of
components (RGBA 4, RGB 3, RG 2, RED or DEPTH_COMPONENT 1) times the size of the type (FLOAT 4, DOUBLE 8,
UNSIGNED_BYTE 1). Those are the cases gl.cc's `ClearTexSubImage` handles.

## What the tracer keeps track of

To size memory behind pointers, the tracer keeps some state for each context (`trace::CtxState`, keyed by the
context `MakeCurrent` made current):

- buffer bindings for `PIXEL_PACK_BUFFER`, `PIXEL_UNPACK_BUFFER` and `ARRAY_BUFFER`. `ELEMENT_ARRAY_BUFFER` is
  tracked per VAO, as in gl.cc. `DeleteBuffer` unbinds what gl.cc unbinds.
- each buffer's size, from its last `BufferData`.
- the range each target has mapped. `MapBufferRange` gives it directly. `MapBuffer` maps the whole buffer bound
  to the target. At `UnmapBuffer` the whole range is copied into the record.
- `GL_UNPACK_ROW_LENGTH`.

## Replaying

`swgl::replay::Replayer` (hidden) decodes each record and calls the same dispatch function. `raster/gltrace`
drives it on one thread, in record order. That order also serialises SwCompositor's worker-thread calls
(`Composite`, `LockResource`, `UnlockResource`, `GetResourceBuffer`).

- Contexts and locked resources are mapped from recorded handle values to the replay's own.
- Generated ids and other results (`GetIntegerv`, strings, locations, `ReadPixels` bytes, buffer sizes) are
  compared with the recording. Any difference is reported once per op on stderr and counted. Later records still
  use the recorded ids.
- Buffers the caller owned (`InitDefaultFramebuffer`, `SetTextureBuffer` with a non-null `buf`) get zeroed
  memory, `stride × height` bytes (`max(height, min_height)` for `SetTextureBuffer`), owned by the replayer.
- The replayer reads color buffers with `GetColorBuffer(fbo, flush = 0)`, calling `cxx` directly, so a pending
  delayed clear is not applied. Applying it would change what later calls draw: gl.cc's `force_clear` with a
  skip rectangle does not clear every row the way a full clear does. `SoftContext::with_frame` reads the
  default framebuffer the same way.
- `gltrace` writes frames top row first. If the trace has had a `Composite` (SwCompositor), it takes the
  default framebuffer as top row first already. Otherwise it flips it, because GL drawing leaves it bottom row
  first (`SoftContext::top_down`).

## Known blind spots

- Memory written by the caller outside a call is not in the trace: through the pointer from `GetColorBuffer` or
  `GetResourceBuffer`, through a mapped buffer outside `Map…`/`UnmapBuffer`, or into a buffer it passed to
  `InitDefaultFramebuffer`/`SetTextureBuffer`. In the replay, that memory holds whatever swgl put there, or zeros.
- `UnmapBuffer` records the mapped range as it is at unmap time. Memory written after the unmap through the old
  pointer is lost.
- The tracer's bookkeeping assumes that the binding and buffer calls for one context come from one thread.
  WebRender works that way. SwCompositor's workers call only `Composite`, `LockResource`, `UnlockResource` and
  `GetResourceBuffer`, and none of these need bookkeeping.
- Timer query results (`GetQueryObjectui64v`) are recorded but not compared, because they measure the run.
