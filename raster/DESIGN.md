# lucinanet-raster: swgl's behaviour in Rust

> 2026-11-11: the Rust rasterizer is the default backend of LucinaNet; `LUCINANET_RASTER=swgl` selects the C++ oracle (swgl stays in the build as the oracle and the benchmark).

The Rust rasterizer that replaces swgl, WebRender's software OpenGL in C++, in LucinaNet. The choice and its
measurements are in `raster/CHOICE.md` and `raster/PERF.md`. This file is the map every porter follows.

## The original is the source of truth

`swgl/` in this repository (swgl 0.70.0, our patches marked `LucinaNet:` in its source) and WebRender's GLSL in
`swgl/res/` define the behaviour, including blend modes, dithering, clears, delayed clears, AA edges,
`clear_caches_with_quads` and the span fast paths
(`swgl_ext.h`). We copy behaviour, not structure, but for this port the
structure is kept close on purpose: one Rust module per C++ file, the same function names in `snake_case`, the same
argument order, so a reviewer can read the two side by side and the per-draw trace diff (below) can point at one function.

Correctness bar: with one thread, the Rust rasterizer gives the **same bytes** as swgl built with `SWGL_STRICT_FP=1`
(no fast-math, no FMA contraction) for every replayed trace on the same machine. The shipped swgl is built with
`-ffast-math`, which lets clang reorder float arithmetic; measured against the strict build (`raster/pixdiff`) it is identical
on the paint page and all 70 Wikipedia frames, and differs on 24 of 26 example-site frames: at most 2,075 pixels (0.1%) a
frame, by at most 4 levels. That is swgl's own noise, and the most the Rust
rasterizer may differ from the shipped swgl. Rust never fuses or reorders float operations, so there is nothing to tune:
a difference from the strict build is a porting bug.

## Crate layout (`raster/core`, crate `lucinanet-raster`)

| Rust module | C++ original | What |
|---|---|---|
| `glsl::vector` | `vector_type.h` | `V2/V4/V8/V16<T>` lane vectors, `CONVERT`, `SHUFFLE`, `combine`, `lowHalf`/`highHalf`, `zip*`, packs |
| `glsl` | `glsl.h` | `Float`, `I32`, `U32`, `Bool`, `vec2..4`, `ivec*`, `bvec*`, `mat2..4`, their `_scalar` forms, GLSL built-ins |
| `program` | `program.h` | `ProgramImpl`, `VertexShaderImpl`, `FragmentShaderImpl` as traits; `Interpolants` |
| `texture` | `texture.h` | texel fetch, nearest/linear sampling, `textureLinear*`, YUV helpers |
| `blend` | `blend.h` | blend keys, `blend_pixels`, masks, AA, `commit_*` |
| `composite` | `composite.h` | `Composite`, `CompositeYUV`, `ApplyMask`, `BlitFramebuffer`, linear/scale blits |
| `rasterize` | `rasterize.h` | `draw_quad`, `draw_quad_spans`, perspective, depth runs, clip |
| `ext` | `swgl_ext.h` | `swgl_drawSpan*`, `swgl_commit*`, span fast paths used by generated shaders |
| `gl` | `gl.cc` | the context: objects, state, uniforms, `DrawElementsInstanced`, clears, uploads, locks |
| `shaders` | generated by `raster/glsl-to-rust` | one module per WebRender shader and feature set, from `swgl/res/*.glsl` |
| `rules` | (new) | pure arithmetic proved by Verus on the shipped file: rect and band bounds, blend table, strides |

`raster/glsl-to-rust` is a fork of `glsl-to-cxx` 0.70 (MPL-2.0): `hir.rs` (parse, types, run classes) is kept, the C++
emitter becomes a Rust emitter. It runs from `raster/core/build.rs` exactly as `swgl/build.rs` runs glsl-to-cxx today, on
the same shader list (`webrender_build::shader::get_shader_features(ShaderFeatureFlags::GL ...)`, same flags as swgl's build.rs).

## Rules for porters

1. **Names.** Types keep their C++ names (`Float`, `I32`, `vec4_scalar`, `WideRGBA8`, `PackedRGBA8`, `IntRect`). Functions
   keep theirs in snake_case only where the C++ is CamelCase; GLSL built-ins keep GLSL names (`texelFetch`, `mix`).
   Allow `non_camel_case_types` / `non_snake_case` where needed.
2. **SIMD.** Lane types are `#[repr(C, align(16))]` arrays (`[f32; 4]`, `[u16; 8]`, ...) with `#[inline(always)]` lane-wise
   operators, which LLVM turns into SSE2/NEON. Wherever the C++ calls an intrinsic (`_mm_rcp_ps`, `_mm_rsqrt_ps`,
   `vrecpeq_f32`, `vrsqrteq_f32`, `_mm_movemask_ps`, saturating packs, rounding modes), the Rust calls the **same**
   intrinsic through `core::arch` under the same `cfg`, because approximate instructions differ between ISAs and the
   bytes must match. Keep a portable fallback that matches the C++ non-SIMD branch. Stable Rust only (no `std::simd`).
3. **No globals.** swgl keeps raster state in statics (`blend_key`, `swgl_ClipFlags`, `swgl_SpanBuf`, `swgl_OpaqueStart`,
   AA distances...). In Rust these live in `RasterState`, one per rasterizing thread, passed as `&mut`. The GL context
   (`gl::Context`) is shared state that only the GL thread mutates.
4. **unsafe.** Allowed in hot pixel loops and texture access, each block with a `// SAFETY:` line naming the bound that
   holds. The bounds themselves (row/stride/offset arithmetic, clipping to the texture) come from `rules`, which Verus checks.
5. **Behaviour of asserts.** C++ `assert` is compiled out in release swgl. Use `debug_assert!` for those. Where the C++
   would read out of bounds in release, the Rust clips instead and the doc comment says so.
6. **Tests.** Each module's tests compare against the C++: `raster/core/tests/oracle/` builds small C++ shims around
   the swgl headers with `cc` (dev-only) and checks bit-equality on random inputs. The whole-system oracle is the trace:
   `raster/gltrace replay --per-draw` on both backends, first differing draw named.

## Parallel rasterizing (after one-thread parity)

swgl draws every target from one thread. Measured on example-site: 98% of swgl's time is per-pixel work in a handful of quad
shaders. The Rust rasterizer splits each large draw across threads by **stripes of 32 rows**. The calling thread runs
the vertex stage once per primitive, in submission order, and publishes what each primitive rasterizes from: its
positions and interpolants, and the raster state and fragment shader (flat varyings included) as its vertex shader left
them. The threads, the calling one included, then **claim stripe indices from one atomic counter** (`fetch_add`,
ascending), and for each claimed stripe draw every primitive of the draw that touches it, in submission order
(`rules::stripe_span`, proved by Verus: its rows lie inside the draw's rows and inside one 32-row word, and every row
lies in exactly one stripe). Each stripe is claimed once, so each pixel still sees the draw's primitives in order from
one thread and blending is exact. Claiming rather than dealing stripes out (`index % n == t`) matters on big.LITTLE
chips: on the SC7180 two A76s take most stripes while the six A55s, often clocked far down, take a few, instead of the
draw waiting for each A55's eighth of the rows. 32 rows because the delayed clear bit vector packs 32 rows per word, so
no word is shared.

A row's delayed clear is resolved by the thread that claimed its stripe, when that thread first shades the row, which is
when one thread would resolve it: `prepare_row` runs only for rows `owns_row` lets through. Each thread works on its own
copy of the clear bits and counter; after the join the context takes back only the words of the stripes each thread
claimed (word `s` holds rows `32 s..32 s + 32`, exactly the rows `rules::stripe_span(s, ..)` can return, as Verus proves)
and subtracts the rows each one cleared. An intermittent mismatch seen on 2026-11-05 (whole rows cleared on the Rust side
that gl.cc had left pending, and segfaults under load) was not this path: a test ran gl.cc without the lock that
serializes its static current context, so its oracle calls went to another test's context. `compare_with` now asserts the
lock is held.

**A thread walks every row of a primitive from its top exactly as one thread does** (edge and interpolant stepping,
a few adds a row) down to the end of the stripe it claimed, and shades only that stripe's rows. A row is never entered directly (`startRow`-style): that
rounds differently from swgl's stepped values, and the difference grows through gradients and blurs. So any number of
threads gives the same bytes as one thread and as strict swgl, on every page (`raster/compare.sh --threads N`).

A draw is split only when the area its primitives cover (their bounding boxes inside the clip rectangle) is above a
threshold (`gl::RASTER_SPLIT_PIXELS`, 64k pixels); smaller draws, and every draw whose target is smaller, stay on the
calling thread.

**A split draw that gets no worker answer for 1 s prints one line to stderr** (`pool::SLOW_WAIT`): the pending
`RasterWorker#n`, their tid, state and last CPU from `/proc/self/task/<tid>/stat`, and the caller's CPU. It exists
because on 2026-11-11 the Juno kernel was found to freeze threads on the Gold CPUs for 1+ s (a timer/wake stall), and
real browsing should show whether draws hit it. One line per slow draw at most. The wait is not abandoned: the workers
call the caller's closure through a lifetime-extended reference, so `Pool::run` may return only after every answer.
